# Consumer 实际体验审计（2026-09-18）

结论：开发者接 API 的基础路径已比较轻，但普通新用户仍需要外部指导；本地正在运行的入口、当前源码、受控 V9 网络不是同一份已交付产品。

## 实际操作及边界

- 读取本机 8110、8111、8112、8113 的 `/health`，全部返回 `mycomesh-consumer/v8`。8111/8112/8113 已解锁，但未读取或输出 API key。
- 重启前，通过内置浏览器打开真实 8111 页面，显示 `Consumer V8`；点击“连接钱包并签名”，得到“未检测到浏览器钱包”。该浏览器没有注入钱包，不能据此判定 Chrome 已安装的钱包也无法使用。
- 重启后，从当前源码以独立数据目录在 8120 启动全新 Consumer。界面已去掉 V8 标题，显示“连接钱包后获取 API 地址和访问密钥。无需填写钱包私钥。”；设备凭证详情默认折叠。再次实际点击连接，在没有钱包的环境中仍只有“未检测到浏览器钱包”的短暂通知，没有钱包安装/选择、手机连接或重试指引。
- 仅检查匿名 `/credentials` HTTP 状态并丢弃正文：8110=423、8111=200、8120=423。8111 是旧的运行版本，不能据当前源码的 management bearer 校验推断它返回 401。当前源码解锁后匿名 401 的隔离测试另见可靠性报告。
- 读取 `/ready`：8111 在约 1.25 秒返回 503，两台旧 443 Relay 没有 V8 Provider；新启动的默认 8120 在约 1.54 秒返回 200，选中 `https://bridge.mycomesh.xyz` 的 GPT-5.5。这证明默认入口仍可能连接另一套可用的 V8 网络，而不是本轮 10443 受控 V9 部署。
- 未用真实钱包完成本轮授权、充值或发送新推理，因此不把完整新人首单闭环写为已通过。历史 V9 糖果调用与本轮用户入口操作分别评价。

本轮临时 Consumer 使用 `.codex-run/mesh/ux-network-audit-20260918/consumer-fresh/`，没有复用用户支付 key、历史账本或真实配置。实际浏览器画面和无钱包错误已在本次对话中检查。

## 发现与优化

| 优先级 | 实证发现 | 优化方向 |
| --- | --- | --- |
| 公开试用前 | 普通入口默认 V8；旧 IP Relay 已没有 V8 Provider，默认域名却仍可选中另一 V8 网络，造成“启动成功但进入的网络不是预期 V9”。 | 将发布包、网络 manifest、合约、模型目录和说明锁定为同一发布版本；页面明确当前网络和可用性。受控试用应有清楚的测试模式，不得伪造独立委员会声明。 |
| 公开试用前 | 当前源码的匿名 credentials 文档命令与管理授权要求不一致，旧运行版本又表现不同。 | 修正文档，并提供受支持的一键配置客户端/复制完整配置操作；升级现存进程后复核，不能以源文件已修改代替运行时交付。 |
| 高 | 无钱包时只有短暂错误；新用户不知道安装什么、如何打开带钱包的浏览器、是否需要 ETH/测试稳定币。 | 先显示只读预检，再让用户选择支持的钱包；提供安装/打开浏览器/重新检测入口，以及分开的测试 ETH 与测试稳定币领取、授权、充值步骤。 |
| 高 | 页面主要展示 URL、Key、Export 和账单，没有从零完成一次受预算保护的试用请求的引导。 | 加“检查连接 → 领取测试额度/完成授权 → 运行第一题 → 查看结果与账单”流程。为开发者保留 API 配置；为试用用户提供最小任务输入与结果下载，不必建设完整聊天产品。 |
| 中 | UI 顶部绿色点由 `chain_error` 是否存在决定，不能证明 Relay 可结算或某个模型可接单。 | 分开展示账户、推理、结算、指定模型可用性；总体状态必须反映当前业务能否成功。 |
| 中 | 页面将所有按钮在异步操作期间禁用；钱包/交易问题多直接显示原始错误，通知约 3.2 秒消失。 | 长任务显示当前步骤、交易链接、是否已发出、是否允许重试；持续保留可操作错误，不要求用户猜测重复点击会不会重复支付。 |

可核查位置：`packages/mycomesh-cli/src/consumer-runtime.mjs:2095`（凭证边界）、`:2287`（首屏）、`:2290`（凭证）、`:2291`（充值）、`:2300`（通知时长）、`:2304`（状态点）、`:2321`（钱包选择）、`:2324`（交易等待）；`docs/local-consumer.md:38`（配置示例）。

建议的钱包发现方式参照 [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963)：支持多个注入钱包的发现与选择，保留旧接口兼容。它本身不能替代无钱包引导或移动端连接。

## 已有优点

Consumer 不依赖 Docker；支付 key 本地保存，正常推理不要求逐次钱包签名。当前源码提供本机管理边界、Key 激活/轮换、消费历史、托管与争议状态、短期分享。应在这些能力上补齐用户流程，不需要推翻现有支付架构。

证据：`.codex-run/mesh/ux-network-audit-20260918/consumer-runtime-status.json`、`consumer-readiness.json`；完整跨组件核验见 `network-product-reliability-audit-2026-09-18.md`。
