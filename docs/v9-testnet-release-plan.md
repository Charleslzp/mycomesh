## 执行顺序

1. **发布基础和干净安装。** 统一依赖/运行时、修复现有测试失败、补 Forge 与本地链 CI，将测试成功绑定发布推广；修复 Makefile V9 默认清单回落、根包运行依赖与 Relay 启动器旧版本固定问题。
2. **V9 运营闭环。** 补部署计划/校验、质押/退出工具、到期 `release` 和 `resolveTimedOutDispute` 处理器。处理器需要唯一执行、持久 outbox、链/合约固定、gas 上限、重复运行及重启恢复；交易成功与业务状态分别校验。
3. **明确部署方案。** 形成实际资产、治理/金库/罚没地址、独立裁决者、争议/裁决/提现窗口、保证金与罚没上限、gas/质押/试用预算表及逐项初始化计划。发现权限与裁决权限分离。确认后才发送对应部署和资金交易。
4. **构建 V9 候选版本。** 用匹配的 Provider/Relay/Consumer、镜像 digest 和清单统一部署；带入广播恢复补丁和强制正文证明；配置受控成员准入和发现证书，保留 V8 历史处理路径。
5. **小规模真网验收。** 覆盖注册/授权/质押、首个请求、托管到期释放、争议成立退款、驳回、超时、提现；同时确认 Consumer 展示与 safe 链状态一致。
6. **可靠性与容量验收。** 多会话并发、同 Provider 续聊、执行中断线不重放、RPC 分歧、广播不确定、重启恢复、目录故障及授权/证书过期；观察 FD/RSS、队列、gas、最老 outbox 和账单收敛。
7. **流式改造。** 首先分段测量 TTFT/排队/生成/RPC/验证开销，再贯通 sidecar→Provider→Relay→Consumer，设计可验证分块与最终回执。未经验证的输出不得直接当作可信工具指令执行。

## 当前发布阻断与剩余验收

- 目前没有实际 V9 Sepolia 部署清单。已新增 `python3 -m gateway.v9_deployment` 部署入口，但真实部署签名方式及裁决成员未落实，尚未发送部署交易。
- 合约到期不会自动执行释放。已补 `plan-release` / `plan-timeout`、持久 outbox 执行与业务结果核验；上线仍须明确执行责任和运行频率，目前没有自动扫描调度服务。
- 多 Relay 对同一 Provider 可用 stake 的读取不等于全网抵押预留，需验证并发暴露控制；限制接入人数不能替代此项验证。
- Makefile 已改为 V9 必须显式指定部署和网络清单，缺失或空值安全拒绝；需在实际 V9 清单生成后验证节点配置。
- 旧 Web 交易路径仍以 V3/V5/V6 为主，V9 首发入口采用已有 V9 支持的原生 Consumer，并做好官网入口说明。
- 部分 V9 构造参数及裁决成员不可变。首发奖励关闭后未来如何启用，需要在部署方案中讲清楚，不能承诺现合约可随时切换；可能需要新的合约部署。
- 至少两位、建议三位独立裁决用户需要实际落实；按用户确定的方案，从自愿参与的高信誉用户中选择，使用本人 Codex 辅助、本人钱包签名。不能生成多个同控测试钱包后将其称为独立用户。[首版 agent](user-jury-agent.md) 已在本地实现，当前仍受 V9 固定名单约束。
