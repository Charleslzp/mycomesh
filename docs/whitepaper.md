# MycoMesh 白皮书

**去中心化 AI 推理网络与其经济模型**

版本 1.0 · 2026 年 10 月 · 对应 V11 协议（Sepolia 测试网部署）

> 本文描述协议设计与当前参数，不构成投资建议或任何形式的要约。测试网上的 tUSDC 与 MYCO 没有价值。参数可能在主网前调整，以链上合约为准。

---

## 摘要

MycoMesh 是一个点对点的 AI 推理市场。需要模型能力的人（Consumer）付费提问，拥有模型能力的人（Provider）作答收费，转发节点（Relay）只转发加密后的请求，看不到内容。支付、托管、定价、信誉和争议裁决全部在以太坊兼容链上执行，合约本身也可以直接调用这个网络（链上推理）。

协议的信任不依赖任何一方的诚实：

- 资金托管在合约里，每笔支付都需要 Consumer 本机签名授权；
- 价格全网统一，按算力利用率每天自动调整，类似比特币的难度调整；
- Provider 不交押金，靠托管期、holdback、敞口上限、免费探针和随机抽取的 AI 陪审团约束；
- 任何第三方都可以出题抽查 Provider，抓到偷换模型的有赏金。

经济模型分两层：

- **稳定币层**：每笔费用 Provider 85%、Relay 5%、国库 10%。
- **MYCO 层**：总量 10 亿、无预挖，按小时出块、周期减半产出。每小时的产出按当小时真实支付的费用分给 Consumer（80%）、Provider（10%）、Relay（7%）和 Keeper（3%）。

## 1. 问题

1. **算力分散，交易不可信。** 大量订阅额度、API 额度和自建模型的算力处于闲置状态，但陌生人之间直接买卖推理没有可信的支付、计量和纠纷处理。
2. **中心化转售平台需要托管资金和看到内容。** 用户必须相信平台不挪用押金、不窥探请求、计费诚实。
3. **"用便宜模型冒充贵模型"难以发现。** 同一个回答，单看一次分辨不出是不是标称的模型给的。
4. **合约用不上 AI。** 链上应用需要分类、审核、仲裁之类的判断，但缺少一个付费、可追责的调用通道。

## 2. 角色

| 角色 | 需要什么 | 做什么 | 收入 |
| --- | --- | --- | --- |
| Consumer | 合约里的一份押金、本机付款 key | 签名授权每个请求，本机解密并核对回答 | MYCO 的 80% |
| Provider | owner 账户和签名 key，不需要押金 | 解密执行、签收据；被抽中时当陪审员 | 费用的 85%，MYCO 的 10% |
| Relay | 有公网 IP 的服务器，不需要域名 | 准入、转发密文、结算、放款、探针、组织陪审、处理链上推理 | 费用的 5%，MYCO 的 7% |
| Keeper | 一个付 gas 的账户 | 批量放款、提交随机数抽陪审、超时结案等兜底调用 | 每次调用的稳定币赏金，MYCO 的 3% |
| 探针方 | 任何人 | 出题抽查 Provider，对偷换模型者立案 | 罚没的一半、MYCO 赏金 |
| 国库 | 协议参数指定的地址 | 收取协议收入 | 费用的 10%、驳回案件的保证金、罚没的剩余部分 |

不存在白名单：Provider 只要在链上把签名 key 绑定到自己的 owner 账户就能接入任何 Relay；Relay 把自己的地址和证书指纹登记到链上目录即可被发现；陪审资格完全由链上结算记录推导。

## 3. 一次请求的生命周期

1. **发现**：Consumer 从链上 Relay 目录找到 Relay，取得 Provider 列表，核对每个 Provider 对其传输密钥的签名。
2. **授权**：Consumer 本机签一份 EIP-712 支付授权（请求哈希、最高费用、指定的 Provider 与 Relay、有效期），并把请求明文加密给该 Provider。Relay 只能看到价格、路由字段和密文。
3. **准入**：Relay 检查押金是否覆盖在途请求、付款 key 的授权和预算、Provider 的未结算敞口与当日产能，然后签派发凭证、转发。
4. **执行**：Provider 核验授权与派发签名，按结算 key 只执行一次，把回答加密回给 Consumer，签一张收据（回答哈希、token 数、实际费用）。
5. **核对**：Consumer 本机解密，核对回答与 Provider 签名的收据一致（流式输出也逐段核对）。
6. **结算**：Relay 把三方签名的收据批量提交上链（`settleBatch`）。合约核验三个签名和网络价，从押金中扣款并托管 24 小时。
7. **放款或争议**：24 小时内 Consumer 可以发起争议，交给随机抽取的陪审团；无争议则由 Relay 或 Keeper 批量放款（`releaseBatch`），按比例分账并记录 MYCO 积分。

## 4. 定价：像比特币难度一样自动调整

全网按模型档位统一定价，Provider 不能自己报价，只在质量和信誉上竞争。

**实际价格 = 档位基础价 × 价格系数**

| 比特币 | MycoMesh |
| --- | --- |
| 难度 | 价格系数（初始 1.0，限制在 0.1× 到 10×） |
| 目标出块时间 10 分钟 | 目标利用率 70% |
| 每 2016 个区块调整一次，每次最多 4 倍 | 每天调整一次，每天最多 ±10% |
| 实际出块速度 | 前一天的利用率 = 已结算工作量 ÷ 在线产能 |

- **需求**：当天链上结算的工作量，按基础价折算，不同模型可以相加。
- **供给**：当天在线 Provider 的计入产能之和。
- **产能有约束**：每个 Provider 每天最多结算自己的计入产能，Relay 在派发前就检查。计入产能等于声明值，但不超过它最好一天成交量的 2 倍；新 Provider 按档位的基础产能（测试网 5 USDC/天）计。
  - 少报产能只会减少自己的收入，而涨价的好处全网共享，所以没有动机少报；
  - 多报受已证明的成交量限制，注册假 Provider 无法压低价格。
- **结果**：接近满负荷时价格上涨，吸引新 Provider；产能闲置时价格下降，吸引新 Consumer。
- **费用规则**：合约强制每笔费用等于网络价，以 Consumer 签的最高费用为上限。

测试网当前档位（单位：每百万 token 的美元价格，未乘价格系数）：

| 档位 | 模型 | 输入 | 输出 | 单次最低费用 |
| --- | --- | --- | --- | --- |
| 1 OpenAI 前沿 | gpt-5.5 | $0.02 | $2.00 | $0.001 |
| 2 Anthropic Claude | claude-sonnet-4-6、claude-opus-4-8 | $0.30 | $1.50 | $0.001 |

> 这组基础价是按"订阅额度近乎零边际成本"设定的，低于官方 API 价格。主网前需要按 API 成本重定档位价格，并把价差大的模型（例如 Sonnet 与 Opus）拆成不同档位。

## 5. 信任与惩罚：没有押金的 Provider 如何被约束

Provider 不交押金，降低接入门槛。约束来自五个方面：

1. **托管期**：每笔费用托管 24 小时，期间可被争议退款。
2. **holdback**：Provider 应得部分的 10% 扣留 7 天，是罚没和举报赏金的来源。
3. **敞口上限**：新 Provider 的未放款费用最多 50 USDC，按干净成交额的 10% 增长，最高 5000 USDC；被确认欺诈后归零重新开始。Provider 最多能骗走的就是自己的敞口和 holdback。
4. **探针**（第 6 节）：免费的已知答案请求，结算前与真实流量无法区分。
5. **陪审团**：
   - 争议开启时，注册表固定候选名单（排除当事各方），用开案 60 秒后的 drand quicknet 随机数抽取陪审员，按各自计入的成交额加权（单人权重上限 100 USDC），drand 签名在合约内用 EIP-2537 预编译验证。
   - 每个陪审员用自己的模型按固定策略判断，签名投票；达到门槛票数一致即生效。
   - 陪审资格由链上记录推导：计入的干净成交额、不同付款方数量、注册时长、欺诈冷却期；每个付款方的计入额有上限，注册空账户刷不出资格。

| 结果 | 处理 |
| --- | --- |
| 确认欺诈 | 费用退给 Consumer；从 Provider 的 holdback 罚没（以费用为限，单案最高 100 USDC），其中 50% 奖励举报人，其余进国库；保证金退还；Provider 信誉清零，冷却 30 天 |
| 驳回 | 正常放款，举报人的 1 USDC 保证金进国库 |
| 陪审超时 | 已抽出陪审则放款，未能组成陪审则退款；均不处罚 |

## 6. 开放探针与能力案：抓"偷换便宜模型"

同一档位全网同价，用便宜模型冒充贵模型就是纯利润。协议把抓作弊开放给所有人，并给予赏金。

**开放探针**

- 任何人都可以当探针方。先提交一个承诺 `keccak256(探针方, 探针 key 的 Merkle 根, 随机盐)`，它不暴露是谁、探谁、什么时候探。
- 用这些 key 发普通的加密请求。答完之后，由请求的主人在争议窗口内作废（`voidProbe`）：退款给探针方，Provider 不收钱。
- 每个 Provider 每天最多 20 次免费探针，所有探针方共用、先到先得，每次不超过 0.05 USDC。Provider 的负担有明确上限。
- 探针 key 由不与探针方关联的账户持有，一批 key 全部用完后才统一作废，Provider 无法事先认出探针。
- 探针结论连同题目、双方明文和 Provider 签名的收据公开发布，并在链上探针记录中登记。任何人都能复核；探针方无法冤枉诚实的 Provider，因为伪造不了 Provider 对错误答案的签名。

**能力案**

一次答错不能定罪，因为前沿模型也会答错难题。偷换模型按统计结果定罪：

1. 探针方提起能力案，必须交出自己在若干个已结束的日子里对该 Provider 作废过的**全部**探针（20–120 道，30 天内）。链上有计数，少交一道都不行，所以没法只挑答错的。
2. 陪审员只从被告所在档位抽取。每个陪审员把每道探针原样在自己的模型上重答，作为对照组，用同一判分规则同时判被告和自己。
3. 判定规则（配对检验）：b 为对照组答对、被告答错的题数，c 为反过来的题数。当单侧精确二项检验 P(X ≥ b | b+c, ½) ≤ 1%，且 (b − c)/n ≥ 10% 时投定罪票。探针方专挑难题没有用，因为难题对对照组一样难。
4. 定罪后，被告的 holdback 被罚没（单案最高 100 USDC），一半给探针方，其余进国库；被告信誉清零；产出合约从结转池给探针方铸造一个块的 MYCO 产出。驳回则没收保证金，超时退还。

探针方可以用自己设计的题目。参考答案出错也冤枉不了人：对照组用同一个参考答案判自己，坏题对双方一样不利。

## 7. 链上推理：合约调用 AI

合约可以通过推理预言机（`MycoInferenceOracleV11`）直接提问，在回调里拿到答案：

1. 合约在结算合约里存押金，调用 `request`：指定档位、模型、问题、最高费用、回调地址与 gas、回调时机、争议人。预言机从押金中锁定最高费用。
2. Relay 监听提问事件，派给同档位、服务该模型的 Provider；Provider 对照链上记录核验后作答一次并签收据。
3. Relay 提交答案（`fulfill`）：合约核验收据、派发签名、档位和网络价，按实际费用扣款托管，差额退回，然后回调。

每个请求只由一个 Provider 作答。大模型的输出无法通过多源比对来证明正确，可信度来自基础层：签名收据、网络价、托管、陪审与罚没，与链下请求完全相同。合约可以选择：

- **立即回调**：约 40 秒拿到答案，自担答案事后被判欺诈的风险；
- **争议期后回调**：等 24 小时争议窗口结束、确认没有被判欺诈后再回调。

问题和答案都公开上链，适合分类、审核、评分、仲裁、Agent 决策等公开场景。合约发起的请求同样产生费用分账和 MYCO 积分，发起请求的合约就是 Consumer。

## 8. 经济模型

### 8.1 稳定币分账

每笔放款的费用：

| 去向 | 比例 | 说明 |
| --- | --- | --- |
| Provider | 85% | 其中 10%（即费用的 8.5%）作为 holdback 扣留 7 天 |
| Relay | 5% | 派发该请求的 Relay |
| 国库 | 10% | 协议收入 |

**国库的收入来源**：每笔费用的 10%、被驳回争议与能力案的保证金、罚没中扣除举报赏金后的剩余部分。

**国库的用途**：

- 支付 Keeper 赏金：每次批量放款或抽陪审调用 0.01 USDC（测试网），从国库注资的赏金池支付；Relay 放款自己的收据不领赏金；
- 项目方的运营收入，以及用协议收入在市场上回购 MYCO。回购属于项目方的经营决策，不是合约强制的规则。

**Consumer 侧没有额外收费**：协议不对托管服务、团队等第三方另外收费。它们的租户交易与普通交易一样分账，项目方的收入只来自真实发生的交易。

### 8.2 MYCO 代币

| 项目 | 参数 |
| --- | --- |
| 总量上限 | 1,000,000,000 MYCO（18 位小数），销毁不会腾出额度 |
| 预挖、团队份额、私募 | 无。唯一的铸币者是产出合约 |
| 出块 | 按时间聚合，每 1 小时一个块（不用 L1/L2 区块，它们太快） |
| 减半 | 第一个周期 1 周，此后每个周期长度翻倍（2 周、4 周、8 周……），最长 4 年，此后每 4 年一个周期；每个周期的产出速率减半 |
| 第一个周期的产出速率 | 约 618,071 MYCO/小时 |

### 8.3 每小时产出的分配

每小时的产出按该小时内**放款**的费用计算积分，分给四类角色：

| 角色 | 份额 | 计分方式 | 何时可领取 |
| --- | --- | --- | --- |
| Consumer | 80% | 本小时付出的费用 | 该小时结束后 |
| Provider | 10% | 本小时服务的费用 × 成功率 | 该小时结束 48 小时后 |
| Relay | 7% | 本小时派发的费用 | 该小时结束后 |
| Keeper | 3% | 本小时放款的费用，以及抽陪审的调用 | 该小时结束后 |

- **成功率** = 放款次数 ÷（放款次数 + 被确认欺诈次数）。按成功率扣掉的部分不发放，留在产出时间表里，滚入以后的块。
- **Provider 延后 48 小时**：确保争议窗口已过、没有未决纠纷后再计算。
- **冷启动保护**：每个块的费用达到下限（测试网 0.1 USDC）才发放全额；不足时按比例发放，其余滚入下一个有交易的小时。没有任何交易的小时，产出整体顺延。
- **能力案赏金**：从结转池中支付，不增加总产出。

**按价值分配，跨模型一致**

积分按实际支付的稳定币计算，与模型、token 数、请求次数无关。不同模型的费用都是同一种稳定币，可以直接相加，所以**每花 1 美元拿到的 MYCO 在所有模型、所有档位上都相同**。这样做的理由：

- 按 token 或请求次数计分，刷量者会集中到最便宜的模型；
- 给每个档位固定一份额度，冷门档位会成为刷量洼地；
- 扣除价格系数后计分，闲置档位每美元能拿多倍 MYCO。

按实际费用计分，以上套利空间都不存在。

### 8.4 各角色的经济账

**Consumer**

付出的每 1 美元在稳定币层换来推理服务，在 MYCO 层按本小时所有 Consumer 支付总额的占比分得 80% 的产出。花得越多分得越多，鼓励大户迁移流量。

**Provider**

- 收入：费用的 85%（其中 8.5% 延后 7 天到账），加 MYCO 的 10% 按成功率分配。
- 成本：模型成本，以及每天最多 20 次、每次不超过 0.05 USDC 的免费探针（每天最多 1 USDC）。
- 无押金，风险敞口受上限约束。

**Relay**

- 收入：费用的 5%，加 MYCO 的 7%。
- 成本：服务器、提交结算和放款的 gas。批量放款每张收据约 2.3–10 万 gas。

**Keeper**

每次调用的稳定币赏金加 MYCO 的 3%。保证即使 Relay 下线，托管的资金也总能被放款、争议总能被推进。

**探针方**

成本是题目本身和每次立案的 1 USDC 保证金；免费额度内的探针不花钱。定罪后拿到罚没的一半、一个块的 MYCO 产出，并取回保证金。

### 8.5 刷量的成本与边界

一个人同时扮演 Consumer、Provider 和 Relay 给自己付费时，费用中的 85% 和 5% 回到自己手里，**真实成本是进国库的 10% 加 gas**。协议对刷量的约束：

- **成本下限**：每刷 1 美元，至少损失 0.1 美元；与刷哪个模型无关。
- **冷启动下限**：清淡时期，一个块的费用达不到下限就只能按比例拿到产出，这限制了用极小额费用拿走整块产出。
- **只计放款的费用**：被争议退款的交易不计分，Provider 份额还要等 48 小时、乘成功率。
- **网络价会被推高**：刷出来的成交量抬高利用率和价格系数，刷量者自己也要按更高的价格付费。

在 MYCO 的市场价值超过约 10 倍刷量成本时，刷量仍然有利可图，这是"交易即挖矿"类设计的固有特性。协议的立场是：刷量者付出的 10% 是真实的协议收入，会流入国库并回购 MYCO；参与者之间的竞争会把刷量的利润压向零。国库地址的全部收支在链上公开，任何人都可以核查。

### 8.6 MYCO 的价值来源

当前协议内没有要求必须使用 MYCO 的功能，价值来自：

1. **国库回购**：协议收入（每笔费用的 10%）用于在市场上回购，回购规模随真实交易量增长；
2. **稀缺性**：总量固定、无预挖、产出随时间减半；
3. **生态用途**：未来可能的治理、质押或费用折扣等用途，需要另行设计和公告，本文不作承诺。

## 9. 治理与升级

- 合约采用 UUPS 可升级代理，测试网阶段由单一管理员控制，没有升级延迟，也没有多签。这是早期迭代的有意取舍：管理员可以修改参数、升级实现，因此理论上能够影响托管资金。
- **承诺截止时间**：管理员可以在链上设置升级截止时间（`setUpgradeSunset`），这个时间只能提前、不能推后，到期后代码永久冻结。
- **单向退出**：先对每个代理调用 `renounceUpgrades()` 永久冻结代码，再调用 `renounceAdmin()` 删除最后一把特权钥匙。之后没有任何人能修改规则或动用托管资金。
- **主网路线**：上线前完成外部审计，设定公开的升级截止时间，并将产出合约与代币合约优先冻结，使"无预挖、总量固定"成为链上可验证的事实。

## 10. 已知风险与局限

| 风险 | 说明与对策 |
| --- | --- |
| 管理员权限 | 测试网阶段管理员可以升级合约。对策：公开升级截止时间，主网前冻结关键合约 |
| 合约未审计 | 当前未经外部审计。对策：主网前审计 |
| Provider 能看到明文 | Relay 看不到，但作答的 Provider 必须看到请求才能执行。不要发送敏感内容；未来可接入可信执行环境 |
| 推理型小模型难以识别 | 开了"思考"的小模型在计算类难题上可以接近前沿模型。对策：开放探针让第三方出考验知识面的题，并参考答题耗时 |
| 供给集中 | 测试网现有 Provider 均由项目方运营，陪审员也是。对策：招募独立 Provider，人数足够后把陪审参数收紧到主网标准（5 人陪审、3 票生效） |
| 订阅转售的合规风险 | 用 ChatGPT 或 Claude 订阅登录对外提供服务可能违反服务条款。对策：推荐 API key 和开源模型接入，并相应调整档位价格 |
| 刷量 | 见 8.5 节 |
| 法律与监管 | 代币、回购和收益分配在不同司法辖区可能受到不同监管，主网前需要专业法律意见 |
| 链上成本 | 回答作为 calldata 上链，链上推理在 L1 上成本高。对策：主网部署在 L2（已在 Base Sepolia 上跑通全流程） |
