# MycoMesh 用户体验与网络评估

检查日期：2026-09-18。关键运行快照为上海时间 15:31–15:32。目标：普通用户可试用、Provider/Relay 受控准入、使用测试币且暂不发代币奖励。

**当前成熟度是可运行的受控工程试验网。核心调用、签名、托管和手动结算已经有真实证据；首次使用、持续接单、到期释放和收益领取仍需要运维介入。最值得优先投入的是完成这条用户闭环。**

## 结论表

| 全网 | 三 Provider、两 Relay、三 Bridge，真实短任务成功并上链 | 仅 3 个推理槽，Sol 仅一路；复杂任务与自动收益闭环未完成 | 能证明可行性，尚不能证明公开试用稳定性 |

## 最影响判断的现场事实

1. **用户入口尚未统一。** 现存 8110–8113 都是 V8。8111 `/ready=503`，其旧 443 Relay 已无 V8 Provider；当前源码默认 8120 `/ready=200`，却选中另一套默认域名的 V8/5.5。此前 V9 成功调用使用专用测试 Consumer。不能把默认 V8 可用计为 V9 用户流程验收，也不能说所有 Consumer 都不可用。
2. **两台 V9 Relay 在线但不能接付费任务。** `ok=true`、`inference_ready=true`，同时 `settlement_ready=false`、`gas_capacity_remaining=0`。当时 gas 价约 1.9953 gwei，750000 gas 预留和 1.5 倍安全系数要求每笔可承诺容量约 0.00224469 测试 ETH；两台余额约 0.00165040、0.00147427，均不足。这是正确拒绝不安全接单，暴露的是资金值守与业务状态展示缺口，不能靠调低安全系数修复。
3. **回答成功不等于 Provider 已收到收益。** 固定区块 11729263，Sol 和 5.5 糖果账单仍为 pending 托管，分别超过可释放时间约 117、133 分钟。交易早已确认，缺的是到期 release 的执行；release 与后续 claim 也应分开显示。
4. **短任务成功，复杂任务还没由网络交付验证。** 糖果题两次成功样本分别为 27.342 秒（Sol）、46.533 秒（5.5），答案识别了题目歧义。但另一次输出超预算在执行后 HTTP 422，用户未收到有效交付/账单。鹈鹕 HTML 最终由指定 Sol 本地 agent 完成，Consumer 请求未提交，不能算成 MycoMesh 网络 HTML 任务成功。
5. **三个 Provider 不等于三个 Sol 备份。** 当前 Sol 仅 Provider2→Relay1；全网推理槽总数为 3。三个 Bridge 是发现冗余，不增加模型执行槽或上游账号额度。不同模型、账号及运营方的故障域需分别统计。
6. **可信度标签应保持准确。** 发现端 Provider reputation 为 0，Relay risk 虽显示 healthy/1.0，但 evidence_count=0、updated_at=0；Provider runtime/upstream/usage integrity 均为 not_verified。签名证明注册身份与内容/付款绑定，不独立证明上游模型身份、用量真实或答案正确。

## 建议实施顺序

### 第一批：公开试用前完成

**A. 交付一致的 V9 试用入口。** 将 Consumer 包、Provider 镜像、manifest、合约、网络名称和文档作为同一发布单元；升级运行实例后再验证，不能只修改源码。普通 V9 独立委员会安全校验保留；若本次继续使用受控测试委员会，应提供单独命名、显式选择、仅测试币的预览入口，清楚说明治理方式，不伪造独立性证明。

验收：新用户按公开入口安装，能看清所连网络，在没有专用 Python 脚本或人工替代操作的情况下完成首单、收到答案并看到正确账单。

**B. 让 Relay 持续拥有可接单能力。** 以“安全可接纳笔数/预计工作时长”配置 gas 预警和受预算约束的补充操作；使用专门运营钱包，保留裁决/结算所需资金。UI 总体可用必须同时考虑推理、结算、指定模型容量；故障中明确告知用户尚未执行或收费。此次人工补 0.00025 测试 ETH 仍不足安全门槛的事实，说明补充流程必须纳入完整预算公式。

验收：low_gas 触发告警与真实不可接单状态，补足后无需手工改配置即可恢复；长期低余额不会等到用户请求失败才被发现。

**C. 自动完成正常账单 release 与合约规定的 timeout。** 复用现有具备持久 intent、确认和幂等保护的操作器，补有界扫描、到期队列、发送者互斥和告警。Provider 页面显示托管、到期待处理、可领取、已到账；最终领取仍由本人钱包按明确交易确认。仲裁观点和退款/罚没裁决不交给 keeper 或 AI 自动替代人类签名。

验收：到期释放在事先约定时间内执行；跨重启、RPC 切换和广播状态未知时不重复发送；无人处理的账单能被告警和恢复。

**D. 明确可交付的 AI 任务与预算。** 当前 2000 输出上限是执行后校验且含推理用量。短期先公布真实任务限制、预检输出预算与模型能力，提供失败恢复说明；复杂代码/HTML 服务需要验证足够且可控制的预算。长期解决原生预算约束或经过计量验证的分段执行，不能以删除超限校验、少报 tokens 或盲目重试替代。

验收：短回答、长推理、代码/HTML、工具输出各有固定任务集；分别记录是否执行、是否交付、实际用量、用户费用和失败原因。HTML 应能下载并离线打开，内容预览与控制台权限隔离。

### 第二批：降低用户负担和恢复成本

- Consumer 用“连接钱包 → 准备测试额度与访问授权 → 运行第一题”的向导；开发者保留一键复制配置和现有 `--codex`。无钱包、缺 ETH、缺测试稳定币、网络不可用分别给出明确下一步，不只显示短暂错误。
- Provider 保留一个可恢复的进度页：“环境检查 → 账户与钱包 → 联网接单”。Docker、模型登录、授权、质押、Relay、Bridge 六个状态可分别诊断；从同一页查看模型资格、试单和收益。
- 模型目录聚合有效 Relay，而不是每次显示随机选中一台的列表；为 Sol 至少配置另一条经过验证的服务路径。显式模型不可用时明确失败，保留已有模型 pin 与签名约束。
- 先显示排队、执行、验签、账单提交状态。当前 buffered SSE 不等于生成中输出文本；真正流式应单独解决内容验证和最终计费收敛。
- 请求派发前持久保存 request ID、请求 hash、目标和预算。POST 断连后显示“结果待核实”，能恢复查询；保留现有未知执行不自动重放的规则。

### 第三批：证明网络质量，再扩大开放

建议把这些作为未来验收目标，当前尚未达成：连续 48 小时在目标并发下运行固定任务集；单 Provider、主 Relay、1–2 Bridge、RPC 和提交器故障有独立恢复记录；不发生重复扣费，未知请求最终可以核实，到期账单得到处理。事先定义成功率分母，分别统计准入拒绝、已接受后失败、用户取消和超预算拒绝。

指标优先采用按模型的成功率、首个状态/首个文本/完整交付延迟、排队和槽位饱和度、结算积压年龄、gas 可服务笔数、lease 剩余时间、到期未释放数量。其方向与 [Google SRE 的延迟、流量、错误、饱和度四类监控](https://sre.google/sre-book/monitoring-distributed-systems/)一致，但具体目标应由 MycoMesh 的固定任务集实测决定，不能用此次健康探测延迟充当推理 P95。

声誉与裁决用户遴选在这些真实事件之上建立：履约、及时响应、证据质量、利益冲突回避与申诉记录分别处理；高声誉用户的 Codex 辅助读证据，用户承担最终签名。当前全零 Provider 声誉和同运营者测试裁决钱包不能宣称已完成独立用户治理。
